現在のテニス乱数表Webアプリの機能・ロジックは変更せず、UI/UXをiPhoneのネイティブアプリのようなデザインに改善してください。

## 基本方針

JavaScript / HTML / CSSの現在の構成を維持してください。

PC向けWebサイトをスマートフォン表示したようなデザインではなく、iPhoneにインストールされたアプリのように見えるUIを目指してください。

Apple Human Interface Guidelinesを参考に、シンプルで視認性が高く、タッチ操作しやすいデザインにしてください。

## 画面設計

iPhoneの縦画面を最優先に設計してください。

画面幅いっぱいに要素を詰め込まず、左右に適切な余白を設けてください。

以下の順序を基本レイアウトとしてください。

1. ヘッダー
2. 試合履歴
3. 現在の試合
4. 出場プレイヤー
5. 休息プレイヤー
6. 操作ボタン

試合履歴と現在の試合は、統一されたカードデザインにしてください。

## iOSらしいデザイン

以下を取り入れてください。

- iOSのシステムフォントを優先
- 過度な装飾を避ける
- 適度な角丸
- 薄い境界線
- 控えめなシャドウ
- 十分な余白
- 明確な情報階層
- 大きく押しやすいボタン
- タップ対象同士の間隔を十分に確保
- PCサイト風の小さなボタンを使用しない
- hoverを前提としたUIにしない

ボタンやカードは画面端ギリギリまで広げず、iPhoneらしい左右マージンを確保してください。

## プレイヤー表示

プレイヤー番号はタップ可能な丸型または角丸ボタンとして表示してください。

出場プレイヤーと休息プレイヤーは明確に区別してください。

各プレイヤーの連続出場回数が直感的に分かるように、色や小さなバッジなどを使用してください。

ただし色だけに依存せず、数字でも連続出場回数を確認できるようにしてください。

プレイヤー入れ替え操作では、タップしたプレイヤーが明確に選択状態になっていることが分かるようにしてください。

## 試合カード

ダブルスの組み合わせが一目で分かるようにしてください。

例：

[ 1 ] [ 4 ]
    VS
[ 2 ] [ 6 ]

単なるHTMLの表ではなく、iPhoneアプリのカードUIとしてデザインしてください。

履歴の試合カードと「次の試合」のカードは基本的に同じレイアウトを使用してください。

## 操作ボタン

「次の試合」など最も重要な操作をPrimary Actionとして明確にしてください。

重要度の低い操作はSecondary Actionとして視覚的に区別してください。

誤操作しやすい操作はPrimary Actionと離してください。

タップ時には視覚的なフィードバックを付けてください。

## Safe Area対応

iPhoneのDynamic Island、ステータスバー、ホームインジケータなどにUIが重ならないようにしてください。

viewport-fit=coverとCSSのenv()を適切に使用し、

- safe-area-inset-top
- safe-area-inset-bottom
- safe-area-inset-left
- safe-area-inset-right

を考慮してください。

特に画面下部に固定ボタンを配置する場合は、ホームインジケータと重ならないようにしてください。

## PWA対応

ホーム画面に追加した場合に、通常のWebページではなくアプリのように表示されることを考慮してください。

既存のmanifest.json、Service Worker、apple-touch-iconなどがある場合は維持してください。

不足している設定があれば追加してください。

## レスポンシブ

iPhoneを最優先にしますが、以下でもレイアウトが破綻しないようにしてください。

- 小型iPhone
- 大型iPhone
- iPad
- PCブラウザ

PCでは画面いっぱいまでコンテンツを広げず、適切なmax-widthを設定して中央配置してください。

## CSS

既存CSSを整理し、デザイン用の値は可能であればCSSカスタムプロパティとしてまとめてください。

例：

--bg
--surface
--text-primary
--text-secondary
--border
--primary
--radius
--spacing

同じ値を各所にハードコードしないでください。

## 重要な制約

現在実装されている以下の機能やロジックは変更しないでください。

- 試合生成ロジック
- プレイヤー管理
- 休息管理
- 連続出場管理
- 履歴管理
- Undo
- 人数変更
- プレイヤー入れ替え

今回の目的は機能追加ではなくUI/UX改善です。

必要であればHTML構造とCSSは大きく整理して構いませんが、既存機能を壊さないでください。

実装後、既存機能がすべて正常に動作することを確認してください。
